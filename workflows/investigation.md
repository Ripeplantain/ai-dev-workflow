# Investigation

Use when the cause, owner, or correct change is not yet known.

1. Define the question, impact, time boundary, and evidence available.
2. Discover relevant code paths, configuration, dependencies, logs, metrics, and recent history.
3. Form hypotheses and test them with the least invasive checks.
4. Record confirmed facts separately from assumptions.
5. Stop when the question is answered or the next experiment requires new access or a change.
6. Report findings, confidence, affected scope, recommended next step, and unresolved questions.

An investigation does not require implementation. Do not edit production code merely to make the investigation feel complete.
