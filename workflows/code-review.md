# Code Review

Use when reviewing a change you did not implement—or when performing the final independent review of your own work.

1. Read the request and acceptance criteria before reading implementation details.
2. Inspect the diff, surrounding code, tests, configuration, and applicable instructions.
3. Evaluate correctness, edge cases, security, architecture, compatibility, performance, tests, and repository hygiene.
4. Prioritize actionable findings by impact. Cite the file/line or behavior and explain the failure mode.
5. Distinguish blockers from suggestions and state what you verified.

Review mindset: “Review this change as though I did not implement it.” A clean review is evidence-based, not a guarantee that no defect exists.
