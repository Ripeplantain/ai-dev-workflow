# Definition of Done

For every relevant item, determine whether it applies and record the evidence.

- [ ] Requirements and acceptance behavior are satisfied.
- [ ] Applicable context and repository conventions were loaded.
- [ ] Existing implementations were reused where appropriate.
- [ ] Existing architecture and boundaries were respected.
- [ ] No unnecessary dependency, abstraction, file, or formatting change was added.
- [ ] Relevant formatting, linting, type checks, tests, and builds pass—or limitations are reported.
- [ ] Error handling, edge cases, and backward compatibility were considered.
- [ ] Security and sensitive-data implications were considered.
- [ ] Documentation, configuration, migrations, and decision records were updated when needed.
- [ ] Temporary/debug artifacts and dead code are absent.
- [ ] The final diff contains no unrelated modifications.
- [ ] Remaining risks, follow-ups, and unverified checks are explicit.

Not every checkbox requires an execution step for every task. “Not applicable” is a valid result when the reason is clear.
