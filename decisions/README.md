# Decision Records

Decision records capture meaningful architectural or product-engineering choices that future contributors need to understand. They are not required for trivial implementation details.

Create a record when a choice changes boundaries, persistence, public contracts, security posture, deployment strategy, or long-term maintenance cost. Use `TEMPLATE.md`, give the file a date and short slug, and link it from relevant documentation when useful.

Keep records immutable after adoption where possible; append a new record when a decision changes.
