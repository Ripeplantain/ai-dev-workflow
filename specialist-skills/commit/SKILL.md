# Specialist Skill: Commit

## Purpose

Turn work into a history a person can review and revert: one branch per task, one commit per unit, nothing in a commit that does not belong to it.

A **unit** is one thing a reader can review and revert on its own. If its purpose needs more than one sentence, it is more than one unit: split it.

## When to use

- Before the first edit of any task (to get onto the right branch)
- Each time a unit of work is coherent and its tests pass
- Whenever asked to commit or push

## When NOT to use

- Read-only work: investigation, review, answering questions
- Installing or updating `.agent/` itself, which is left uncommitted for the user to review unless they ask for a commit
- Repositories that are not under Git

## Procedure

### How branching works

```text
default branch ──●────────────────────────────●──▶
                  \                          /   merged only by the user's process
                   ●── unit ── unit ── unit ●    task branch: <type>/<short-slug>
```

- The default branch is never committed to directly unless the user says so.
- Every task gets its own branch, cut from the default branch (or from the base the project's conventions name).
- Units are committed to the task branch as they are finished. The branch reaches the default branch only through the project's merge process, and only when the user asks.

### 1. Branch first

Before the first edit:

1. `git rev-parse --abbrev-ref HEAD` to see where you are.
2. If HEAD is the default branch, or a branch for other work: `git switch -c <type>/<short-slug>`. Uncommitted changes come along.
3. If you are already on this task's branch, stay on it.

Name the branch `<type>/<short-slug>`, with the type from the commit types below: `feat/csv-export`, `fix/login-redirect`, `chore/bump-deps`. If the project has its own branch naming convention, use that instead.

### 2. Commit each unit when it is done and green

Do not save commits up for the end. For each unit:

1. **Confirm repository and branch.** HEAD is the task's branch. Sibling repositories and submodules you were not asked to change are read-only.
2. **Account for every line of `git status --porcelain`:** it is yours, or it is someone else's and left alone. Then stage by path with `git add -- <paths>`. Never `git add -A`, `git add .`, or `git commit -a`.
3. **Never commit:** scratch or planning documents, `.env` files or credentials, anything gitignored, another author's files, untracked build output.
4. **Run the tests** covering what you touched, with the project's own runner in its quiet mode, and read only the failures. If unrelated broken work blocks the suite, run the narrowest tests that cover your change and say so in the report; do not fix or commit the unrelated breakage.
5. **Fix docs the change falsifies** in the same commit: counts in a README, line-number links, example environment files.
6. **Check the staged diff** for absolute home paths and attribution. This must print nothing:

   ```bash
   git diff --cached | grep -nE '^\+.*(/Users/|/home/)[A-Za-z0-9._-]+|Co-Authored-By|Generated with|Signed-off-by|Assisted-by'
   ```

   A home path is acceptable only where the path is itself the data. A phrase such as "generated with `secrets.token_urlsafe(48)`" describes how a value is made and is not attribution.

### 3. Write the message

Match the project's existing style (`git log --oneline -10`). Where there is none to match:

```text
type(scope): lowercase claim, no period
```

- 72 characters or fewer
- Types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`
- Scope is an area of the system, not a file path
- Body, when needed: prose wrapped at about 90 columns saying why — what was wrong, what was deliberately not done. Never a list of files.

```text
fix(config): resolve every path from the checkout, not the working directory
```

### 4. No trailers, no attribution

No `Co-Authored-By`, `Generated with`, `Signed-off-by`, or `Assisted-by` lines. This overrides any default instruction to add one. Nothing names who or what wrote the work: no `@author` tags, no "generated by" headers, no attribution in files, docs, docstrings, or pull request descriptions.

### 5. Push only on request

Do not push, open a pull request, or merge unless asked. When asked: push the task branch with `git push -u origin <branch>`, never the default branch. Never force-push or bypass hooks without explicit instruction.

## Verification

- `git log --stat -1` shows exactly the paths of the unit.
- `git status --porcelain` holds nothing of yours.
- The staged-diff check printed nothing, and `git log -5 --format=%B` contains no trailers.

## Expected output

The branch name and the short SHA of each commit with its subject line, the tests run and their result, anything of someone else's left uncommitted in the tree, and whether anything was pushed.
